# Choke Point — architecture notes

The detailed design notes for `games/choke-point/`, moved out of the root [CLAUDE.md](../../CLAUDE.md) so they load when you work in this directory rather than on every session (Claude Code picks up a `CLAUDE.md` in the directory it is working in). The root file keeps the rules that break things; this file has the reasoning and the model. Read it before changing the engine or the shell here. Past decisions are in [docs/DECISIONS.md](../../docs/DECISIONS.md).

A grid tower-defense — placement + economy, not reflex. Reuses two patterns from
earlier games rather than inventing anything.

- **[engine.js](engine.js)** — pure logic, seeded LCG only.
  - **Enemy movement is Flak Battery's arc-length model**: `buildPath(L)` turns a fixed `route` of `[col,row]` waypoints into a polyline with cumulative `s`, and `atS(path, pathLen, s)` gives the pixel position at any distance. An enemy is just a `dist` that grows by `speed·dt`.
  - **Rotation is Feedline's transpose trick.** `LAYOUT_TALL` is the exact transpose of `LAYOUT` (COLS×ROWS ↔ ROWS×COLS, same square `CELL`), and the route is transposed cell-for-cell. Because cells are square the two paths have an **identical length**, so `relayout` maps towers `(c,r)→(r,c)` and leaves every enemy's `dist` untouched — lossless, and no pace rescaling needed (a flat px/s speed is already layout-independent). Tests pin the transpose and the equal length.
  - `TOWER_TYPES` (node/breaker/coil/sever) is a base stat line plus two words per class: `spec` (the armory track it buys cheap) and `weak` (the one it buys dear). Everything resolves through **`stats(w, tower)`** — base × level × class upgrades — and nothing should read `base` directly. **Every base stat must be non-zero**: `stats` grows them multiplicatively, so a zero base makes that whole armory track a silent no-op however it is priced — that was live on Coil *and* Node's splash for two builds (Node's is its `weak` track, so the armory charged a surcharge for nothing). A test now asserts every track moves a stat on every class. Targeting is the same for all three: `step` acquires a target by the tower's `priority` (`first`/`last`/`strongest`) every frame. Node and Coil are **hitscan** — damage lands on the frame they fire, and `fx.shot` is the beam the shell draws. **Breaker is not**: it pushes a homing round onto `w.slugs` (`SLUG_SPEED`, `stepSlugs`) and *nothing* resolves until that round arrives — the stat line is captured at the muzzle, a target that dies mid-flight releases the round to burst where it was aimed, and `fx.launch`/`fx.impact` bracket the flight. Slugs are not snapshotted and do not survive `relayout`. Don't make the other two projectiles: a bolt of light arriving late reads as broken rather than heavy.
  - **Towers level themselves; money buys the class.** A tower carries `xp`/`level` (1–10) and gains XP for damage that *lands*, capped at the target's remaining health plus `XP_KILL_BONUS` — uncapped, a Breaker parked over the spawn would level on wasted overkill. There is no `upgradeTower`. What scrap buys is the **armory**: four tracks (`CLASS_TRACKS`) bought per class through `buyClassUpgrade`, priced with `SPEC_DISCOUNT`/`WEAK_PENALTY`. Two numbers are stated requirements and pinned by tests: a level-10 Breaker reaches exactly 3 cells, and 4 with the range track maxed.
  - **The armory has to stay a choice.** It is permanent, so filling it means the game solves itself for good rather than for a run — and at v40 prices a full armory cost **1.9x** what a whole Easy run pays in bounty, so two runs bought everything. `CLASS_BASE_COST`/`CLASS_COST_STEP` now put it at **~24x** across four classes and all six tracks (~15x for the four tracks anyone can buy), measured 2026-10-13. The test pins a floor (`> 8`) as a ratio rather than a total, so retuning has to stay honest about it — but it pins no ceiling, and it counts raw kill bounty, ignoring what a run spends on towers, so the real time to fill is longer still.
  - **No tower may share a colour with another tower *or with an enemy*.** Coil was `#5fc9a4` — a near neighbour of Node's blue and the exact value the Patch enemy uses, so the healer you most want to pick out looked like your own tower. A test enforces it.
  - **A harder win earns content** (`CLASS_UNLOCK`/`TRACK_UNLOCK`/`hasSweep`/`rewardsFor`): Sever for a Medium circuit, the Chain track for a Hard one, Veterancy and circuits 4-5 for holding one circuit on all three. The world carries a *projection* of that (`w.unlocked`, set by `syncUnlocks`) exactly like Flak Battery's `gunUnlocks` — never snapshotted, so a save cannot smuggle a class past current progress. **`buyClassUpgrade` checks both gates**: a locked class has no armory column to buy either, since the armory never resets and a purchase for a tower you cannot place would be a permanent waste. The sweep gate is **additive**: circuits 1-3 keep the per-difficulty ladder, or an Easy-only player would be stranded on circuit 1 forever. Anything locked is **drawn with its requirement on it**, never hidden.
- **The armory persists across runs, but the engine touches no storage.** `w.classUpgrades` lives on the world so `stats` stays the only place numbers come from; the *shell* loads and saves it (guarded localStorage, same pattern as `shared/levels.js`). `resetGame` deliberately leaves it alone — carrying over is the whole point. `DIFFICULTIES` (easy/medium/hard) is the counterweight, scaling `hpScale` and the opening purse.
  - `wavePlan(wave)` is a pure, escalating spawn schedule; `startWave` queues it onto a timeline `step` releases over time (player-triggered, giving a build phase), with groups **overlapping** by `GROUP_OVERLAP` so a wave arrives as a mixture rather than a queue. **Rush is a latch** (`setRush`, `w.rushing`, `RUSH_RATE`): while it is on the *spawn clock* runs faster and nothing else changes — **not** the same thing as the shell's fast-forward, which speeds up the whole simulation, and the verb was deleted once on that mistaken assumption (see DECISIONS). It refuses to latch on with nothing queued, and releases itself when the queue empties. Economy: `components` (kill bounty in, build/armory out, partial `sellValue` refund), `integrity` (a leak decrements; 0 = over), endless. **A build price is `buildCost(w, type)`, never `TOWER_TYPES[type].cost`** — every tower standing makes the next dearer (`crowdingMult`, quadratic, ~5.9x at 24 towers). `sellValue` is deliberately half the *list* price, so the crowding premium is not refunded and moving a tower stays cheaper than rebuilding it.
  - `ROUTES` are **ordered by difficulty**, longest/easiest first (~36 / 31 / 14 cells). They are **earned, not cycled**: `resetGame` goes to the route it is told and nothing else — it used to advance on every call, which meant *losing* promoted you to a harder board.
  - **Waves are tagged.** Every spawn and every enemy carries the `wave` it belongs to, and `waveBeaten(w, n)` asks whether wave *n* is done — everything it would send released, nothing it sent alive. Waves overlap and the shell auto-starts, so "the board is clear" may never happen; the win used to wait for it and could go a run without firing. An **untagged** spawn or enemy counts as wave 1 and therefore blocks, which is the safe direction for a resumed pre-v41 save.
  - **Every tenth wave is a surge** (`isSurgeWave`): the same wave arriving harder — `SURGE_COUNT` more of everything, tighter gaps, `SURGE_HP` tougher. Scaling the plan rather than writing a separate one keeps every enemy the wave would normally contain, so nothing a player has learned stops applying at the moment it matters most.
  - **The game can be won.** Each difficulty has a `winWave` (50 / 100 / 150). The check is a **state** — at the wave, and the board clear — asked every frame, *not* the wave-clear edge it was in v29: waves overlap and Auto refills the board, so that edge could go a whole run without firing and the win was unreachable. `wavesCleared` is counted apart from `wave` for the same reason. Clearing it sets `won` and the one-frame edge `justWon` for the shell to catch. `won` is in the snapshot (so a resumed run is not congratulated twice), `justWon` is deliberately not. A won run can continue — the banner offers both — and the core can still break afterwards.
  - **The player-facing word for a board is "circuit", never "route"** — the engine keeps `routeIndex`/`ROUTES`/`routeAt`, and the shell must not surface either word.
- **Progression is a pure function over a plain object**: `newProgress`/`sanitizeProgress`/`routeUnlocked`/`unlockedRoutes`/`difficultyUnlocked`/`recordWin`. Circuits unlock one at a time per difficulty, and **difficulty is earned per circuit**: `difficultyUnlocked(progress, difficulty, routeIndex)` asks whether the difficulty below was won *on that board*. Passing no `routeIndex` answers the older global question, which is what a menu listing difficulties before a circuit is chosen needs. It used to be one win anywhere, so beating Easy on the opening circuit opened Hard's entry on boards never played. The *shell* stores it (`PROGRESS_KEY`), same split as the armory, and `readDifficulty` re-checks the gate so a stored value can't smuggle a locked difficulty back in. `DEFAULT_DIFFICULTY` is `easy` and `START_COMPONENTS`/`START_INTEGRITY` derive from it — don't hardcode a difficulty in either.
  - Public API mirrors the others plus TD verbs: `canBuild`/`buildTower`/`sellTower`/`setPriority`, `canMove`/`moveTower`/`moveCost`, `buyClassUpgrade`/`classCost`, `startWave`/`rushWave`, `cellAt`/`towerAt`, `towerReady`, `relayout`.
  - **Moving a tower** costs exactly `sellValue` — the money a sell-and-rebuild would burn, so it is never a worse deal than the workaround and never free. Level and XP survive (earned by fighting, not bought); the cooldown resets so a move can't double as a free reload. Allowed mid-wave on purpose.
  - `towerReady` takes an optional margin, and the shell wakes on `READY_MARGIN` but sleeps on `READY_SLEEP_MARGIN` — plus a hold timer of its own. **Both are needed**: hysteresis covers a target loitering on the threshold, the timer covers gaps between targets.
  - **Where a barrel points is shell state, not `t.aim`.** `t.aim` is only set for an enemy inside *firing* range, but a tower stays deployed on the looser reach plus the hold timer — so there is a window where it is out and `aim` is null. The shell keeps its own eased bearing (`aimAngle`), tracking the nearest enemy within the waking reach and holding its last bearing otherwise. Drawing straight up in that window was the "turret doesn't point at the target" bug.
  - `DROP_CHANCE` lives inside `rollDrop` in Flak Battery for a reason worth copying: the coin flip and the kind come from **one** LCG advance, so one carrier is one advance whether or not it drops. Outside the function, the drop *sequence* would depend on how many carriers died and a seeded run would stop replaying.
- **[choke-point.html](choke-point.html)** is the fullest shell: the standard layout/rotation/pause + help + audio + scores wiring from Hull Breach, plus a **`#controls` strip** (tower palette, a four-button wave row, and a full-width armory button), a tap-a-tower targeting/sell popup, and the armory modal. It is also the only game using `makeFit`'s **`fillWidth`** — paired with `body.scrolls` from the theme, because that mode can push furniture below the fold and the default `overflow:hidden` would make it unreachable. Towers draw as bare rings until `towerReady` says something is near, then grow a hub and slide a barrel out.
- **[engine.test.js](engine.test.js)** — board/transpose invariant → path geometry → building → levelling → armory → difficulty → tower firing (range/cooldown/splash/slow) → targeting priority → enemies (movement/kill/leak) → waves/rush → rotation (lossless round-trip) → full-run sanity.
  - Note the `overlook(w, type, span)` helper: it searches for a buildable cell that genuinely covers a stretch of route. Its predecessors assumed the first empty cell was next to the path, which held only because route 0 used to start in the corner — reordering the routes broke a dozen tests at once for reasons unrelated to what any of them tested.
- **Render test but no standalone build** — [render-test.mjs](render-test.mjs) inlines the shell in memory, same as Hull Breach and Feedline. It covers the full enemy roster with every trait cue, all three tower types across the level range, both idle and deployed tower art, the armory driven through real DOM clicks, the palette staying put when you go broke, and a live run deep enough to include Shell, Phase and Patch.
